<Layer kind="concept">

Everything in the earlier chapters ends up in two numbers: what a task costs, and how long it takes. Both are sums over the model calls, and the calculator above computes them the way the engine does: pick a task and a policy, and the engine runs it (in your browser, in a background thread) and takes every call apart.

<span id="ha-cost-parts" />

Per call, the **cost** has three parts: the prompt tokens not in the cache, at the input price (or the cache-write price, if the prompt is being cached); the prompt tokens read from the cache, at a fraction $\rho$ of that (a tenth on most models, less on the newest; [chapter 4](/learn/04-prompt-caching) has the table and the maths); and the output tokens, at several times the input price. On a reasoning model the output includes **thinking tokens**, which are billed as output too. The **time** has two: the time to the first token, which grows with the uncached prompt, and the decode time, which grows with the output. Around the calls come the tools, the human's answers and any back-off.

<span id="ha-calc" />

<Layer kind="maths">

For model call $t$ with $I_t$ prompt tokens, $K_t$ of them read from the cache, and $O_t$ output tokens,

$$
C = \sum_t \big[(I_t - K_t)\,p_{\text{in}} + K_t\,p_{\text{cache}} + O_t\,p_{\text{out}}\big],
$$

where $p_{\text{in}}$ becomes the cache-write price $p_{\text{write}} = w\,p_{\text{in}}$ on a call whose prompt is written to the cache, and $p_{\text{cache}} = \rho\,p_{\text{in}}$. On a reasoning model each call also generates $R_t$ thinking tokens, which add $R_t\,p_{\text{out}}$ to the cost and $R_t / r_{\text{decode}}$ to the time. With $R$ thinking tokens a call over $n$ calls, the output side grows by $nR$ while the input side, $\sum_t I_t$, does not change (the engine does not keep thinking in the context), so output becomes the larger part of the bill once $nR\,p_{\text{out}}$ plus the answers' cost exceeds the prompt's cost. Each call's time is a fixed overhead $t_0$, plus the uncached prompt at the prefill rate, plus the output at the decode rate; a run adds the tools, the waits for the human and any back-off:

$$
T = \sum_t \Big[t_0 + \frac{I_t - K_t}{r_{\text{prefill}}} + \frac{O_t}{r_{\text{decode}}}\Big] + \sum t_{\text{tool}} + \sum w .
$$

Because the whole context is re-sent on every turn ([chapter 1](/learn/01-the-agent-loop)), $\sum_t I_t$ grows roughly with the square of the number of turns, while $\sum_t O_t$ grows linearly: without reasoning, long tasks are input-bound, which is why caching ([chapter 4](/learn/04-prompt-caching)), compaction ([chapter 3](/learn/03-the-context-budget)) and sub-agents ([chapter 6](/learn/06-sub-agents)) all go after $I_t$. Where $r_{\text{prefill}}$ and $r_{\text{decode}}$ come from (the roofline of the hardware serving the model, batching, and the prefill/decode split) is the subject of [LLM Inference Explained](https://llm-inference-explained.vercel.app/learn/10-serving-metrics); how a serving system trades them against each other, including prefix caching, of [Inference Trade-offs Explained](https://inference-tradeoffs-explained.vercel.app/learn/03-prefix-caching).

</Layer>

<Layer kind="code">

One call's cost and latency, cut from the vendored engine ([`accounting.ts`](https://github.com/BrendanJamesLynskey/agent-harnesses-explained/blob/main/src/lib/engine/vendor/accounting.ts)):

```ts
const fresh = input - cached;
const rate = stored ? price.cache_write : price.input;
return (cached * price.cache_read + fresh * rate + output * price.output) / 1e6;
```

```ts
const ttft = profile.overhead_ms + ((input - cached) * 1000) / profile.prefill_tps;
return [ttft, ttft + (output * 1000) / profile.decode_tps];
```

<Remember>

- Cost per call: fresh prompt tokens at the input (or write) price, cached ones at ρ times it, output at the output price.
- Time per call: a fixed overhead, the uncached prompt at the prefill rate, the output at the decode rate.
- Without reasoning, input dominates; thinking tokens are output, and they flip that.
- People and slow hardware dominate the time: an approval or a CPU costs more than any token.
